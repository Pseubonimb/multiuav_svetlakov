# Ведомые «по пути ведущего» (`line_follow`)

Файл: `multiuav/algorithms/line_follow.py`. Имя в сценарии: `line_follow`.

Ведомые идут за ведущим колонной, на поворотах проходят там же, где он, и не срезают
углы, хотя не видят ни ведущего (если он далеко), ни стен. Интервал держится не по прямой,
а по длине пройденного пути.

## Что знает ведомый

| Есть | Нет |
| --- | --- |
| своя скорость и угловая скорость (одометрия, с ошибками) | GPS |
| передняя камера: направление и расстояние до видимых соседей | номеров соседей, их числа, кто из них ведущий |
| | связи по радио |
| | лидара, карты стен |

Это видно по коду:
- из наблюдений сразу берутся только расстояние и направление (`_camera`), номер соседа
  отбрасывается;
- кадры одному соседу сопоставляет собственный трекер (`_track`) по близости к прогнозу;
- аргумент `leader` и дальномер `me.ranges` не читаются;
- истинное состояние своего дрона (`me`) используется только как источник показаний
  своих датчиков, к которым добавляются ошибки (`_odometry`): ошибка масштаба скорости,
  шум, дрейф гироскопа.

Тест `tests/test_line_follow.py::test_uses_neither_ids_nor_leader_nor_lidar` проверяет:
если перемешать номера соседей, убрать `leader` и подсунуть случайный дальномер, команды не
меняются.

Каких соседей «видит камера», решает `multiuav/perception.py` (дальность, заслонение
зданием, ошибка `perception.noise`). Алгоритм дополнительно оставляет только передний сектор
`fov_deg` и учитывает, что ближний дрон заслоняет дальнего.

## Как работает

Каждый шаг управления (20 раз в секунду):

1. **Где я.** Счисление пути по своей скорости и гироскопу в собственной системе отсчёта
   от точки старта.
2. **Кого вижу.** Отметки камеры переводятся в эту систему, α-β фильтр даёт положение и
   скорость каждого видимого соседа. Сосед впереди — ближайший в секторе ±60° от курса.
3. **Куда лететь (изолиния).** Ведомый записывает, где пролетел сосед впереди (каждые 0,5 м).
   Сосед сам на пути своего соседа, и так до ведущего, поэтому запись — это путь ведущего.
   Запись сглаживается скользящим средним с поправкой на усадку: `2·S(p) − S(S(p))`
   («сглаживание дважды» по Тьюки). Простое среднее скругляет угол внутрь, и у каждого
   следующего дрона скругление добавлялось бы к предыдущему; поправка убирает основную часть
   этого сдвига, почти не теряя подавления шума.
4. **Где я на этом пути.** Проекция себя на запись: боковое отклонение `delta` и
   `L = σ(сосед) − σ(я)` — расстояние до соседа по пути.
5. **Скорость.** `v = v_соседа + k·(L − distance)` и два ограничения:
   - безопасная скорость по модели Гиппса: если сосед резко затормозит, остановиться
     не ближе `d_min` по прямой;
   - `v ≤ √(a_turn / κ)`, где κ — кривизна записанного пути впереди: перед поворотом
     дрон заранее сбрасывает скорость.
6. **Курс.** Скользящий режим, как при выходе на изолинию:
   `S = sin(ψ − ψ_пути) + μ·arctg(delta / b)`, `u = −u_max·насыщение(S / ε)`.
   Направление пути берётся на `look` м впереди своей проекции.

Камера (курс корпуса) смотрит на соседа впереди, а летит ведомый туда, куда велит закон
курса: квадрокоптеру это не мешает, а сосед так не уходит из кадра на повороте и курс не
«качается» вместе с поправками скользящего режима.

Пока сосед впереди виден, ведомый держится за того же дрона, что и в прошлом кадре
(ближайшего к прогнозу). Если сосед пропал (скрылся за углом), ведомый не угадывает,
куда тот полетел: долетает по записи почти до места, где видел его последним (`d_lost`), и
оттуда видит снова. На повороте круче ~90° сосед уходит за край кадра передней камеры —
тогда ведомый, долетев до этого места, поворачивается туда, куда сосед летел, и ищет его
только в этой стороне (±45°), чтобы не принять за соседа дронов, идущих следом.

Точки записи «назад» (дрожание отметки вдоль линии взгляда) отбрасываются; «назад» —
против скорости соседа, а шаг больше 2 м записывается всегда, поэтому запись не может
«застрять» (в первой версии могла — и ведомый срезал угол). Высоту каждый держит свою начальную. Клавиша L сажает ведомых, как у
`visual_follow`.

## Запуск

```
python -m multiuav run scenarios/line_corner.yaml --out runs/line_corner --plot runs/line_corner.png
python -m multiuav run scenarios/line_city.yaml --out runs/line_city --plot runs/line_city.png
scripts/demo.sh -s scenarios/rc_line.yaml        # с пультом в Unreal
scripts/demo.sh -s scenarios/rc_line.yaml -k     # с пультом в упрощённом симуляторе
python -m pytest -q tests/test_line_follow.py
```

- `line_corner.yaml` — один поворот, ведущий по точкам.
- `line_city.yaml` — три поворота и остановка ведущего на 4 с посреди улицы (`stop_and_go`).
- `rc_line.yaml` — то же, что `rc_group.yaml`, но ведомые `line_follow` и передняя камера.
- `line_blocks.yaml`, `line_blocks_city.yaml` — 3D в Cosys-AirSim на сцене Blocks без пульта:
  ведущий — автопилот `stop_and_go`, 7 дронов, высота 30 м; во втором вдоль маршрута стоят
  дома (их ставит в сцену `examples/spawn_walls.py` после каждого запуска сцены):

```
python -m multiuav settings scenarios/line_blocks.yaml --write
# запустить сцену Blocks и дождаться её загрузки
python -m multiuav run scenarios/line_blocks.yaml --backend cosys --out runs/lb --plot runs/lb.png
python examples/spawn_walls.py scenarios/line_blocks_city.yaml
python -m multiuav run scenarios/line_blocks_city.yaml --backend cosys --out runs/lbc --plot runs/lbc.png
```

## Важные параметры

- **`clock`.**
  - `sim` — время по симулятору. Нужно для упрощённого симулятора: с большим числом дронов
    он считает медленнее реального времени.
  - `auto` (по умолчанию) — большее из модельного и настоящего прошедшего времени. Нужно в
    Unreal, где цикл управления может отставать от rate_hz.
- **`perception.lidar_range`.** В симуляторе заслонение соседа стеной проверяется по
  дальномеру. Поэтому его дальность нужна не меньше дальности камеры, хотя сам алгоритм
  дальномер не читает. В Unreal лидары у 7 дронов заметно замедляют сцену (время симулятора
  отстаёт от настоящего, и одометрия по часам завышает пройденный путь — ведомые поворачивают
  раньше времени). Поэтому в `line_blocks*.yaml` лидаров нет (`lidar_range: 0`), а заслонение
  соседа домами имитирует сам `line_follow` по домам из сценария (`world_from`).
- **`k_vel`, `look`, `eps` для Unreal.** В Unreal команды исполняются с запаздыванием
  (наклон, сеть, цикл 10 Гц). С настройками для упрощённого симулятора ведомые там
  раскачиваются вокруг пути, и раскачка растёт к хвосту: в прогоне на Blocks отклонение
  росло от 2 м у первого ведомого до 7 м у шестого. Поэтому в `line_blocks*.yaml` и
  `rc_line.yaml` стоят `k_vel: 1.0`, `look: 4` (направление пути берётся на 4 м впереди) и
  `eps: 0.6` (мягче возврат на путь). На модели с запаздыванием наклона 0,15–0,6 с и
  задержкой команд до 0,2 с город с домами с этими настройками проходился во всех
  прогонах, а с прежними — только при малом запаздывании. Плата — поворот чуть
  «скругляется» (до ~3–4 м внутрь у 7 дронов), поэтому для длинных колонн в узких улицах
  нужна проверка.
- **`debug: true`** — печатать в терминал, когда сосед пропал из кадра и когда путь
  записывается заново, а раз в 10 с — совпадает ли время алгоритма со временем симулятора
  (для разбора полётов в Unreal).
- **`smooth`.** `twice` (по умолчанию) — сглаживание с поправкой на усадку угла;
  `mean` — простое скользящее среднее (первая версия: хвост длинной колонны срезал углы).

## Результаты (упрощённый симулятор форка)

Шум — ошибка камеры `perception.noise` и ошибка одометрии (×1: масштаб 2 %, шум 0,02 м/с,
дрейф гироскопа 0,002 рад/с). Успешный прогон — все дошли, столкновений нет.

| Сценарий, дронов | Камера 3 %, одометрия ×1 | Камера 5 %, одометрия ×2 | Камера 7 %, одометрия ×2 |
| --- | --- | --- | --- |
| `line_corner`, 5 | 8/8 | 8/8 | 3/8 |
| `line_city`, 5 | 8/8 | 8/8 | 7/8 |
| `line_city`, 10 | 6/6 | 6/6 | — |
| `line_city`, 30 | 2/2 | 2/2 | — |
| `line_city`, 50 | 1/1 | — | — |

При шуме до 5 % дроны не подлетали друг к другу ближе 4,7 м, а в колоннах до 10 дронов
до стены оставалось не меньше 3,2 м. При 50 дронах хвост проходит внутренний угол в 0,7 м
от стены — это близко к пределу (см. правило ниже). При ошибке камеры 7 % и больше алгоритм
ненадёжен.

## Сколько дронов пройдут поворот: правило

Каждый ведомый идёт по копии пути соседа, и на повороте копия чуть «скругляется» внутрь.
Скругления копятся вдоль колонны. Серия опытов (колонна из 30 дронов; поворот на 45°, 90°,
135°; скорость ведущего 3, 6, 9 м/с; шум камеры 3 и 5 %; со стенами и без) показала, что
дрон номер k срезает угол относительно пути ведущего не больше чем на

    e(k) ≈ a·√k,   a = 0,7 м   (с запасом по всем опытам)

Растёт как √k, а не как k: повторное сглаживание острого угла похоже на диффузию — радиус
«размытия» растёт как корень из числа повторений. Острее и медленнее угол ведущего — тем
больше a: поворот на 90° со скоростью 3 м/с (радиус поворота ведущего ~1 м) даёт
a ≈ 0,6; плавный поворот на 45° со скоростью 6–9 м/с (радиус 4–7 м) — a ≈ 0,1.

Отсюда правило: колонна из N дронов проходит поворот, не задев внутренний угол, если

    a·√N ≤ h − m,   то есть   N ≤ ((h − m) / a)²,

где h — расстояние от пути ведущего до внутреннего угла минус радиус дрона (0,4 м),
m — запас (0,5 м). Например, ведущий летит по середине улицы:

| Ширина улицы | h | Не больше дронов (a = 0,7) |
| --- | --- | --- |
| 4 м | 1,6 м | 2 |
| 6 м | 2,6 м | 9 |
| 8 м | 3,6 м | 19 |
| 10 м | 4,6 м | 34 |
| 14 м | 6,6 м | 75 |

Если пилот прижимается к внутренней стороне поворота, h меньше — и дронов меньше.
Проверка на `line_city` (улица 10 м): 30 и 40 дронов проходят с запасом, 50 — с зазором
0,8 м; правило с a = 0,7 даёт 34, то есть оно осторожнее опыта.

Условия, при которых правило проверено:
- **поворот не круче 135°**; разворот на месте (U-образный) не поддерживается;
- **цепочка не рвётся**: ведущий не уходит от первого ведомого дальше дальности камеры
  (40 м). Ведомые перед поворотом тормозят, поэтому пилоту на крутых поворотах тоже нужно
  сбрасывать скорость: поворот на 90° проходился на скорости до 9 м/с, на 135° — на 3 и
  6 м/с (при шуме камеры 5 % и 6 м/с один прогон из двух оборвался), а на 9 м/с ведущий
  убегал, и колонна останавливалась (без столкновений). Прогоны с обрывом в оценку a
  не входят;
- **шум камеры не больше 5 %**;
- **упрощённый симулятор**: инерции наклона мало. В Unreal дрон после поворота ещё и
  выносит наружу (в прошлых прогонах до 1–2,5 м, не растёт вдоль колонны) — это
  ограничение на внешнюю стену: h_внеш − вынос > 0, от N не зависит.

Гарантия здесь статистическая (по 2 прогона на вариант), поэтому запас m лучше не убирать.

## Ограничения

- **Накопление вдоль колонны** — см. правило выше.
- **Обрыв цепочки.** Если дрон выбыл или ведущий убежал дальше дальности камеры, те, кто
  позади, зависают там, где видели соседа последним.
- **Сдача назад.** Алгоритм рассчитан на то, что ведущий летит вперёд. Если пилот сдаёт
  назад, ведомые этого не повторяют и только притормаживают по безопасной скорости.
- **Колебания в Unreal.** В прежней версии (Cosys, сцена Blocks, 7 дронов, три поворота)
  столкновений не было, но после поворота ведомые раскачиваются вокруг пути с размахом
  до ~5 м из-за инерции дрона.
