# Модели дрона в MultiUAV + Cosys-AirSim: команды, параметры, сопротивление воздуха

Как запускать дрон с разной «резвостью», какие физические параметры при этом меняются и как в симуляторе устроено сопротивление воздуха.

Всё ниже касается бэкенда `cosys` (Unreal + Cosys-AirSim). В упрощённом симуляторе `kinematic` своя модель, о ней — в конце.

---

## 1. Что должно быть сделано заранее

Быстрые модели и сопротивление винтов — это **доработки плагина Cosys-AirSim**, их нет в исходном AirSim. На этой машине они уже наложены и собраны (`airsim_patches/`, см. `airsim_patches/README.md`):

| Патч | Что даёт |
|---|---|
| `02-fast-model.patch` | ключ `"Model": "Fast<k>"` — тяга ×k и перенастроенные под неё регуляторы |
| `03-propeller-drag-area.patch` | исправленная площадь винтов в сопротивлении корпуса |
| `04-rotor-drag.patch` | ключ `"RotorDrag": k` — сопротивление винтов |

Без патчей (например, на готовой сборке карты Виталия `~/Desktop/Karta_Vitali/Blocks.sh`) ключи `Model` и `RotorDrag` молча игнорируются: летит обычный дрон без сопротивления винтов.

**Главное правило:** модель и сопротивление записываются в `~/Documents/AirSim/settings.json`, а Unreal читает этот файл **только при старте игры** (Play или запуск `-game`). Поменяли модель — перезапустите игру.

## 2. Команды

Все команды — из папки проекта с включённым окружением:

```bash
cd ~/Documents/multiuav_svetlakov && source .venv/bin/activate
```

### 2.1. Всё одной командой (`scripts/demo.sh`)

Скрипт сам пишет `settings.json`, запускает Unreal, окно камер и полёт. Модель — опция `-o`, сопротивление винтов — `-r` (с/м).

Один дрон с пульта (сценарий `rc_single.yaml`, без ведомых):

```bash
scripts/demo.sh -s scenarios/rc_single.yaml -f 0 -m acro -o fast2.5 -r 0.035
```

Ведущий с пульта и 4 ведомых (сценарий `rc_group.yaml`):

```bash
scripts/demo.sh -o fast2.5 -r 0.035
```

Остальные опции не меняются: `-m althold|acro` — режим пульта, `-f N` — число ведомых, `-M cesium` — карта, `-k` — без 3D. Полный список — `scripts/demo.sh -h`.

**Режим AltHold/Acro в этих сценариях задаёт тумблер пульта**, а не `-m`. В `rc_single.yaml` и `rc_group.yaml` прописан `mode_switch: {axis: 4, acro_above: 0.0}`: тумблер на оси 4 в одном положении — AltHold, в другом — Acro. Опция `-m` (и `--mode` у `run`) работает, только если строку `mode_switch` закомментировать.

### 2.2. Готовые варианты

| Как летит | Команда (один дрон, Acro) |
|---|---|
| Исходный AirSim: тяжёлый и «на льду» | `scripts/demo.sh -s scenarios/rc_single.yaml -f 0 -m acro -o generic -r 0` |
| Обычный дрон, но с «сцеплением» | `scripts/demo.sh -s scenarios/rc_single.yaml -f 0 -m acro -o generic -r 0.035` |
| **Рекомендуемый для пульта** — резвый и управляемый | `scripts/demo.sh -s scenarios/rc_single.yaml -f 0 -m acro -o fast2.5 -r 0.035` |
| Быстрее на прямой, больше скользит | `scripts/demo.sh -s scenarios/rc_single.yaml -f 0 -m acro -o fast2.5 -r 0.02` |
| Тяга поменьше, мягче на стиках | `scripts/demo.sh -s scenarios/rc_single.yaml -f 0 -m acro -o fast2 -r 0.035` |
| Очень «цепкий», но медленный | `scripts/demo.sh -s scenarios/rc_single.yaml -f 0 -m acro -o fast2.5 -r 0.05` |

С тумблером из сценария режим переключается на пульте прямо в полёте; `-m acro` в командах выше — на случай, если `mode_switch` закомментирован. Для группы уберите `-s … -f 0`.

### 2.3. По шагам (если Unreal открываете сами)

```bash
python -m multiuav settings scenarios/rc_single.yaml --model fast2.5 --rotor-drag 0.035 --write
```

Затем откройте Unreal и нажмите Play:

```bash
ue5 "$HOME/Downloads/Blocks 5.8/Blocks.uproject"
```

И запустите полёт:

```bash
python -m multiuav run scenarios/rc_single.yaml --backend cosys --mode acro
```

`--model` и `--rotor-drag` у `settings` перекрывают ключи `model` и `rotor_drag` в сценарии. Без них берётся то, что записано в сценарии (`rc_single.yaml` и `rc_group.yaml`: `fast2.5`, `0.035`).

Проверить, что попало в файл:

```bash
grep -E '"Model"|"RotorDrag"' ~/Documents/AirSim/settings.json
```

### 2.4. Замер модели без пульта (`scripts/physics_tests/run_model.sh`)

Скрипт сам пишет `settings.json`, запускает Blocks, гоняет тестовые манёвры одного дрона и закрывает Unreal. Перед запуском Unreal должен быть закрыт.

```bash
scripts/physics_tests/run_model.sh fast2.5
```

```bash
RD=0.035 TESTS=glide,top,turn,brake scripts/physics_tests/run_model.sh fast2.5
```

```bash
ALT=1 scripts/physics_tests/run_model.sh generic
```

- `RD` — сопротивление винтов, с/м (по умолчанию 0);
- `TESTS` — манёвры: `step` (рывок по крену), `turn` (поворот вектора скорости на 90°), `brake` (торможение), `glide` (скольжение без наклона), `top` (предельная скорость на 60°);
- `ALT=1` — ещё и проверка AltHold (`althold.py`);
- три числа после модели, например `run_model.sh fast2.5 "0.4 0.3 0"`, — свои коэффициенты P, I, D регулятора угловых скоростей.

## 3. Модели дрона

У автопилота SimpleFlight в Cosys одна рама — **Generic**: квадрокоптер на 1 кг, винты 22,9 см (как у DJI Phantom 2). Быстрые модели `Fast<k>` — та же рама с более мощными моторами.

| Модель (`model` / `-o`) | Тяга ×k | Тяга/вес | Газ висения | Наклон, AltHold | Вращение, Acro | P угловых скоростей | Проверено в Unreal |
|---|---|---|---|---|---|---|---|
| `generic` | 1 | 1,7 | 0,59 | до 32,7° | до 2,5 рад/с (143°/с) | 0,25 | да |
| `fast` | 1,3 | 2,2 | ≈0,45 | до 45° | до 5 рад/с (286°/с) | 0,19 | частично |
| `fast2` | 2 | 3,4 | 0,29 | до 45° | до 5 рад/с | 0,125 | да |
| `fast2.5` | 2,5 | 4,3 | 0,24 | до 45° | до 5 рад/с | 0,10 | да |
| `fast3` | 3 | 5,1 | ≈0,20 | до 45° | до 5 рад/с | 0,083 | нет |
| `fast4` | 4 | 6,8 | ≈0,15 | до 45° | до 5 рад/с | 0,0625 | нет |

`k` — любое число от 1 до 4, например `fast2.2`. Вне этого диапазона, а также просто `fast`, плагин берёт 1,3.

Замеры (раздел 22 файла опыта; один дрон, команды 50 раз в секунду):

| | generic | fast2 | fast2.5 |
|---|---|---|---|
| Рывок по крену на 300°/с: время до 90 % | 42–62 мс | 42 мс | 82 мс |
| Поворот вектора скорости на 90° при 15 м/с: время, снос вперёд | 2,3 с, 17 м | 1,7 с, 9 м | 1,7 с, 9 м |
| AltHold: подъём на 10 м | 2,4 с | 1,9 с | 2,0 с |

### 3.1. Какие физические параметры меняет `Fast<k>`

**1. Тяга винтов.** Тяга одного винта считается по стандартной формуле:

T_max = C_T · ρ · n² · D⁴

- C_T = 0,1099 — коэффициент тяги винта (безразмерный, замерен для винта DJI Phantom);
- ρ ≈ 1,225 кг/м³ — плотность воздуха;
- n — обороты в секунду (у Generic максимум 6397 об/мин ≈ 106,6 об/с);
- D = 0,2286 м — диаметр винта.

У Generic это 4,18 Н на винт, 16,7 Н на четыре. При весе 1 кг × 9,81 м/с² = 9,81 Н отношение тяги к весу ≈ 1,7.

Патч умножает максимальные обороты на √k, тогда тяга растёт ровно в k раз (тяга ∝ n²). Реактивный момент винтов, от которого дрон поворачивается по рысканью, растёт так же (∝ n²). Масса, моменты инерции, размеры рамы и винтов не меняются.

**Что это даёт физически.** Отношение тяги к весу — главная характеристика «резвости»: оно ограничивает, насколько сильно дрон может наклониться, не теряя высоту, и какое боковое ускорение он способен развить. При горизонтальном полёте предельное боковое ускорение ≈ g·√((T/W)² − 1): у Generic ≈ 13,5 м/с², у Fast2.5 ≈ 40 м/с².

**2. Пределы прошивки.**

| Предел | Generic | Fast<k> | Где действует |
|---|---|---|---|
| Наклон в AltHold (`angle_level_pid.max_limit`) | π/5,5 = 32,7° | π/4 = 45° | стики крена и тангажа в AltHold |
| Угловая скорость (`angle_rate_pid.max_limit`) | 2,5 рад/с | 5 рад/с | стики в Acro и внутренний контур AltHold |

**3. Регуляторы, поделённые на k.** Это не физика, а настройка автопилота под новую тягу. Регуляторы выдают команду в долях газа (0…1). Когда та же доля газа даёт в k раз больше силы, каждая поправка становится в k раз сильнее, и дрон раскачивается. Поэтому делится на k:

- P регулятора угловых скоростей (было 0,25);
- P и I регулятора вертикальной скорости;
- минимальный газ удержания высоты `min_throttle` (было 0,3). Без этого при k = 2 висение на газе 0,29 оказывалось ниже минимального 0,3, и в AltHold дрон не мог снизиться: однажды улетел на 112 м.

### 3.2. Параметры в сценарии MultiUAV

Это пределы стиков на стороне MultiUAV, раздел `limits:` в YAML. Они переводят положение стика в команду, а прошивка потом сама обрезает команду по своим пределам из таблицы выше.

| Ключ | Что значит при полном отклонении стика | В `rc_group.yaml` |
|---|---|---|
| `max_tilt_deg` | AltHold: угол наклона | 32 |
| `max_yaw_rate_deg` | скорость поворота по рысканью, °/с | 180 |
| `max_climb` | AltHold: скорость подъёма, м/с (прошивка — до 6) | 6 |
| `max_rate_deg` | Acro: скорость вращения по крену и тангажу, °/с | 200 |
| `hover_throttle` | Acro в `kinematic`: газ висения (в Unreal не используется) | 0,5 |

Для быстрых моделей можно поднять `max_tilt_deg` до 45 и `max_rate_deg` до 280: прошивка Fast<k> это разрешает, а Generic срежет до 32,7° и 143°/с.

Ещё один необязательный ключ — `rate_gains: {p: …, i: …, d: …}`, свои коэффициенты регулятора угловых скоростей. По замерам на Fast2.5 все пробованные варианты были хуже встроенных: перелёт до 540°/с вместо 300, раскачка при резком торможении. Без этого ключа работают коэффициенты плагина.

## 4. Сопротивление воздуха (air drag)

### 4.1. Физика: два разных сопротивления

Полная сила сопротивления движению тела в воздухе обычно записывается как

F = −b·v − c·v·|v|

- **c·v²** — сопротивление формы (давления). Воздух, который тело расталкивает, уносит импульс ∝ ρ·A·v². Растёт с квадратом скорости и главенствует на больших скоростях.
- **b·v** — линейное сопротивление. У обычного тела это вязкое трение, оно мало, и им пренебрегают. **Но у вращающегося винта есть большое линейное сопротивление другого происхождения.** Когда винт движется боком сквозь воздух, лопасть, идущая навстречу потоку, получает больше подъёмной силы и сильнее тормозится, чем отступающая. Диск винта наклоняется назад, и появляется сила против скорости, пропорциональная тяге винта. Это называют **rotor drag** (сюда входят индуктивное сопротивление и «завал» лопастей, blade flapping).

У небольших квадрокоптеров на обычных скоростях **rotor drag больше сопротивления корпуса**. Именно из-за него отпущенный дрон быстро «встаёт» и его не несёт по инерции.

### 4.2. Как сопротивление корпуса устроено в AirSim

Файл `FastPhysicsEngine.hpp`, функция `getDragWrench`. Дрон заменён коробкой с шестью гранями (вперёд/назад, влево/вправо, вверх/вниз). Для каждой грани, которая движется навстречу воздуху:

F_грань = −½ · C_d · A_грань · ρ · v_n²

- v_n — составляющая скорости вдоль нормали грани (скорость берётся относительно ветра, с учётом вращения дрона). Грани, идущие «от воздуха», пропускаются, как и скорости меньше 0,1 м/с;
- C_d = 0,325 (`linear_drag_coefficient`, у Generic 1,3/4);
- A_грань — площадь грани коробки 18 × 11 × 4 см плюс вклад четырёх винтов:
  - сбоку (вперёд и вбок) — «ребро» вращающегося диска: π·D·h, где h = 1 см;
  - сверху и снизу — площадь диска винта π·D²/4;
- сила прикладывается в точке грани, поэтому даёт ещё и момент — угловое сопротивление.

Площади граней у Generic:

| Грань | Площадь | Сила при 15 м/с |
|---|---|---|
| спереди | 0,033 м² | 1,5 Н, торможение 1,5 м/с² |
| сбоку | 0,036 м² | 1,6 Н |
| сверху/снизу | 0,184 м² | — |

Сверху площадь в 5–6 раз больше, чем спереди. Поэтому чем сильнее дрон наклонён, тем больше «парусит» его верхняя сторона.

**Найденная ошибка (патч 03).** В исходном коде площадь диска считалась как π·D² вместо π·D²/4: верхняя грань была 0,68 м² вместо 0,18 м², как будто дрон летел под зонтиком. Это давало вязкий разгон и странное «чем сильнее наклон, тем медленнее». После исправления в Acro на 45° дрон разгоняется до 31,8 м/с вместо 25,7.

**Линейного члена в AirSim нет.** В коде прямо написано: «total drag is b·v + c·v·v but we ignore the first term as b << c». Для винтов это неверно, и без rotor drag дрон скользил, как по льду: с 15 м/с без наклона катился 145 м.

### 4.3. Сопротивление винтов (патч 04)

Добавлено в `FastPhysicsEngine::getRotorDragWrench`:

**F = −k · T · v⊥**

- T — суммарная тяга винтов в данный момент, Н;
- v⊥ = (vₓ, v_y) — скорость дрона относительно ветра в **осях корпуса**, поперёк оси винтов. Вдоль оси (вверх-вниз по корпусу) эта сила не действует;
- k — коэффициент, с/м. Это ключ `"RotorDrag"` в settings.json (`rotor_drag` в сценарии, `--rotor-drag` в `settings`, `-r` в `demo.sh`).

**Почему пропорционально тяге.** Чем сильнее крутятся винты, тем сильнее асимметрия лопастей и тем больше эта сила. Дрон, у которого выключены моторы, её не испытывает.

**Как понимать k.** На висении T = m·g, и уравнение движения превращается в

dv/dt = −k·g·v,

то есть скорость затухает экспоненциально с постоянной времени τ = 1/(k·g). При k = 0,035 с/м: k·g ≈ 0,34 1/с, τ ≈ 2,9 с. За это время скорость падает в e ≈ 2,7 раза. Ровно такое затухание (0,35 1/с) всегда было в упрощённом симуляторе `kinematic`, поэтому там дрон «на льду» не скользил.

**Замеры на Fast2.5** (раздел 23 файла опыта):

| k, с/м | Скольжение с 15 м/с без наклона: до 7,5 / до 2 м/с, путь | Скорость на 60° за 10 с | Разгон 0→20 м/с на 45° | Поворот 90° на 15 м/с |
|---|---|---|---|---|
| 0 | 11 с / >15 с, **145 м** | высоту не удержал | 2,4 с | 1,7 с, снос 9 м |
| 0,02 | 2,8 / 8,8 с, 55 м | 28 м/с | 4,0 с | 1,6 с, 9 м |
| 0,035 | 1,6 / 5,1 с, **31 м** | 23 м/с | не за 10 с | 1,6 с, 7 м |
| 0,05 | 0,8 / 3,4 с, 18 м | 20 м/с | не за 10 с | не успел за 8 с |

**Плата за сцепление — потолок скорости.** Сила растёт со скоростью линейно, и наклон в какой-то момент её уже не перебарывает. Чем больше k, тем «цепче» дрон, но тем ниже его предельная скорость.

### 4.4. Как управлять сопротивлением

| Что | Как менять | Нужна пересборка плагина? |
|---|---|---|
| Сопротивление винтов k | `rotor_drag` в сценарии (по умолчанию 0,035), `settings --rotor-drag`, `demo.sh -r`; затем перезапуск игры. Это же k берёт `kinematic` (`run --rotor-drag` — сразу) | нет |
| Сопротивление корпуса (C_d, размеры коробки) | только в коде плагина: `MultiRotorParams.hpp` (`linear_drag_coefficient`, `body_box`) | да |
| Площадь винтов в сопротивлении корпуса | патч 03 (уже наложен) | да |
| Ветер | AirSim: `simSetWind` из Python или `"Wind"` в settings.json. Обе силы считаются от скорости **относительно воздуха**, поэтому ветер действует и на корпус, и на винты. MultiUAV ветер пока не задаёт | нет |

**Подбор k на практике:**
- 0 — исходный AirSim, «лёд»;
- 0,02 — быстрее и дальше катится, потолок около 28 м/с;
- 0,035 — рекомендую для полётов с пульта, похоже на `kinematic`;
- 0,05 — очень цепко, но медленно.

## 5. Упрощённый симулятор `kinematic`

Здесь нет ни моделей, ни патчей. Дрон — точка с массой, а движение задают несколько констант в `multiuav/backends/kinematic.py`:

- сопротивление винтов — та же формула и то же k, что в Cosys (`rotor_drag` в сценарии, по умолчанию 0,035): по горизонтали dv/dt = −k·(T/m)·v, где T/m — тяга на единицу массы (на висении g, с наклоном больше). На висении это −0,34·v. Вертикаль в Acro гасится отдельно, `vertical_drag = 0,35` 1/с;
- наклон и вертикальная скорость догоняют команду с задержкой (`tilt_tau = 0,15 с`, `climb_tau = 0,3 с`);
- в Acro тяга считается от газа и `hover_throttle` из сценария.

Одно k на оба симулятора: поставили `rotor_drag: 0` — «на льду» дрон катится и в `kinematic`, и в Unreal. Сопротивление корпуса ~v² и инерция винтов есть только в Unreal, поэтому совпадение приблизительное.
